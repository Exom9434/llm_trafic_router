## 요약: 지금 어디에 있고, 무엇이 부족한가

이 프로젝트는 이미 파일럿 수준을 넘어섰다. 4개 상용 프로바이더(OpenAI, Anthropic, Google, Qwen)를 28일간 하루 2회 벤치마크했고, 데이터 정제·통계 분석 파이프라인(`analysis/`)과 컴파일된 LaTeX 논문(`report/main.tex`)까지 갖췄다. 따라서 과제는 "논문을 새로 쓰는 것"이 아니라 "파일럿을 심사 통과 수준으로 끌어올리는 것"이다.

현재 초안의 결론 자체는 합리적이다. 그러나 심사자가 보면 세 층위에서 약점이 드러난다. 첫째는 통계적 타당성이다. 지금의 유의성 수치는 부풀려져 있어 재분석이 필요하다. 둘째는 데이터 완전성이다. 유효 표본이 너무 적다. 셋째는 실험 설계의 교란 요인이다. 시간대와 피크 효과가 분리되지 않는다. 이 세 가지가 "블로그 글"과 "논문"을 가르는 핵심이다.

아래는 영향력과 작업량을 기준으로 우선순위를 매긴 로드맵이다. **P0는 재수집 없이 지금 데이터로 당장 가능**하고, P1·P2는 실험 재실행이 필요하다.

## P0 — 지금 데이터로 당장 (재수집 불필요)

### P0-1. 통계 재분석: pseudoreplication 수정 (최우선)

현재 `03_peak_nonpeak_analysis.py`는 Mann–Whitney U 검정을 1,890개 개별 호출(row)에 통째로 적용한다. 문제는 이 row들이 독립 표본이 아니라는 점이다. 실제로는 complete slot 7개(peak 4 / nonpeak 3)에서 나온 반복 측정이다. 같은 세션 안의 360개 호출은 그날의 서버 부하와 네트워크 상태를 공유하므로 서로 강하게 상관된다.

즉 **실질 표본 크기는 세션 수준의 n=7이지, 호출 수준의 1,890이 아니다.** 검정을 호출 단위로 돌리면 표본을 인위적으로 270배 부풀리는 셈이고, 그 결과 `p<0.001` 같은 수치가 나온다. 심사자가 가장 먼저, 그리고 가장 강하게 지적할 지점이다.

**해결 방안 (둘 중 하나, 혹은 둘 다):**

1. **슬롯 단위 집계 후 비교 (간단).** 각 slot의 median TTFT를 먼저 계산한 뒤, peak 4개 값 vs nonpeak 3개 값을 비교한다. 표본이 작으므로 Mann–Whitney 대신 정확 검정(exact test)을 쓰고, 유의성 주장은 매우 신중하게 한다. 이 경우 "n=7로는 유의성을 논하기 어렵다"는 정직한 서술이 오히려 논문의 신뢰도를 높인다.

2. **혼합효과모형 (권장, P2-2와 연계).** `TTFT ~ condition + (1 | provider) + (1 | day)` 형태로 day/slot을 랜덤효과로 넣어 위계 구조를 반영한다. 반복 측정의 상관을 통계적으로 흡수하므로 호출 단위 데이터를 버리지 않고도 올바른 추론이 가능하다.

**산출물:** 재분석 스크립트, 수정된 Table 2~4, 정직하게 조정된 유의성 표기.

### P0-2. 정확도 측정 방식 보정

`gpt-4o-mini`의 정확도 49%는 초안에서 "엄격한 단일 문자 포맷에 대한 민감성" 때문이라고 설명한다. 그러나 리뷰어는 이를 **모델 성능이 아니라 측정 도구의 결함**으로 읽는다. MMLU에서 gpt-4o-mini가 49%일 리 없기 때문이다.

**해결:** (a) 파싱 로직을 더 관대하게 만들어 실제 답을 포착하고, (b) 정확도를 "파싱 성공 건에 한정한 정확도"와 "포맷 실패율"로 명확히 분리 보고한다. 이렇게 하면 두 수치 모두 해석 가능해지고, 포맷 실패율 자체도 흥미로운 부차적 결과가 된다.

### P0-3. Related Work 섹션 신설

현재 초안에는 관련 연구 섹션이 아예 없다. 논문의 기여가 "새롭다"는 것을 입증하려면 기존 문헌과의 위치 설정이 필수다.

**다뤄야 할 영역:** LLM serving/inference 지연 특성 연구, 클라우드 성능 변동성(performance variability) 측정 문헌, API SLA/모니터링 연구, MMLU 등 벤치마크의 측정 방법론. 이들과 대비해 "소비자 관점에서, 종단적으로, 시간대별 부하 효과를 측정"한 점이 이 연구의 차별점임을 명시한다.

## P1 — 실험 재실행 (핵심 데이터·설계 보강)

### P1-1. Google 429/503 해결 + 실패 격리

`analysis`가 보여주듯 54개 실행 슬롯 중 complete는 단 7개다. 주범은 Google Gemini의 HTTP 429/503 rate-limiting이고, 한 프로바이더가 죽으면 세션이 통째로 조기 종료되는 구조라 피해가 증폭된다. 이 한 가지가 통계력 부족의 근본 원인이다.

**해결:**

- Google 호출에 지수 백오프(exponential backoff) 재시도 로직 추가
- Google API 유료 티어로 전환해 rate limit 상향
- 프로바이더 간 호출 간격 증가 (현재 2초)
- **실패 격리:** 한 프로바이더가 실패해도 나머지 3개는 계속 기록되도록 예외 처리 (현재는 세션 전체가 중단됨)
- 목표: complete slot을 최소 수십 개 확보

### P1-2. 다시간대 슬롯 + 호출 순서 랜덤화

현재 설계의 가장 큰 교란은 **시간대(time-of-day)와 피크 효과가 분리되지 않는다**는 점이다. 측정 시점이 10:00 ET(peak)와 22:00 ET(nonpeak) 딱 둘뿐이라, 관찰된 차이가 "피크 부하" 때문인지 "오전 vs 밤"이라는 시간대 고유 효과 때문인지 구분할 수 없다.

**해결:**

- 하루 4~6개 시점으로 측정 슬롯 확대 → 피크를 이분 변수가 아니라 **연속적 트래픽 프록시**로 다룰 수 있음
- 매 사이클마다 프로바이더 호출 순서를 랜덤화 (현재는 OpenAI→Anthropic→Google→Qwen 고정) → 순서 편향 제거

### P1-3. 네트워크 기저선(ping) 분리

모든 측정이 residential 네트워크의 Mac Mini에서 이뤄진다. 네트워크 지터가 TTFT에 섞여 있어 서버측 지연과 분리되지 않는다.

**해결:** 매 호출 직전 각 엔드포인트에 대한 ping 또는 TCP handshake 시간을 함께 기록한다. TTFT에서 이 기저선을 빼면 순수 서버측 지연에 근접한다. 낮은 비용으로 측정 신뢰도를 크게 높이는 조치다.

## P2 — 심화 (논문의 격을 올리는 부분)

### P2-1. Qwen 아시아-피크 가설 직접 검증 (잠재적 최대 novelty)

초안은 "Qwen이 US 피크에 오히려 빠른 건 US 피크 = 아시아 논피크이기 때문"이라고 해석한다. 그러나 이는 **현재 검증되지 않은 추측**이다. API 수준 측정만으로는 확인할 수 없다고 스스로 인정하고 있다.

여기에 반증 가능한 예측을 붙이면 관찰이 인과 논증으로 바뀐다. 아시아 피크 시간대(예: 베이징 업무 시간)에 측정 슬롯을 추가하면, 가설이 옳다면 **그 시간대에 Qwen이 느려져야 한다.** 이 예측이 맞으면 단순한 이상치 관찰이 아니라 "지역별 사용자 분포가 API 성능에 미치는 영향"이라는 검증된 발견이 되고, 이것이 논문의 가장 독창적인 기여가 될 수 있다.

### P2-2. 혼합효과모형 정식 도입

P0-1의 연장선에서, 최종 분석을 혼합효과모형으로 통일한다. provider를 고정효과, day와 slot을 랜덤효과로 두면 반복 측정의 위계를 올바르게 반영하고 프로바이더별 효과를 동시에 추정할 수 있다. 방법론 섹션의 신뢰도를 결정적으로 높이는 부분이다.

## 권장 실행 순서

1. **1주차 (P0):** 통계 재분석, 정확도 보정, Related Work 작성 — 재수집 없이 현재 원고를 즉시 개선. 이 단계만으로도 "정직하고 방법론적으로 건전한 파일럿 논문"이 된다.
2. **2주차 (P1 코드):** 실험 스크립트에 백오프·실패 격리·다시간대·랜덤화·ping 기저선을 반영해 배포.
3. **3~6주차 (P1·P2 재수집):** 개선된 파이프라인으로 수십 개 complete slot 확보. Qwen 아시아-피크 슬롯 포함.
4. **이후:** 혼합효과모형으로 최종 분석, 원고 개정, 목표 학회/저널 투고.

## 참고: 목표 지점에 따른 조정

- **워크샵/짧은 논문이 목표라면** P0만 충실히 해도 투고 가능하다. "파일럿"임을 명시하고 정직하게 한계를 서술하는 전략.
