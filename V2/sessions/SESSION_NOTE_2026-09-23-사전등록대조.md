# 2026-09-23 OSF 등록본과 실제 실험을 대조하고 중단 규칙 두 건을 코드에 맞췄다

### 한 줄 요약

9월 11일에 올린 OSF 등록본(9월 10일판 영문 전문과 `osf_upload` 파일 다섯 개)을 러너 코드와 대조해 어긋남 여덟 건을 찾았다. 본실험 전이므로 코드와 문안을 고친 뒤 OSF 등록 업데이트로 반영하기로 했다. 이번 세션에서는 그중 4번(모델 단위 중단)과 5번(선불 잔액 가드)을 코드에 반영했다.

### 어긋남 여덟 건

1. 묶음 구성. 부록 README는 `bank_order` 연속 100개씩이라 적었으나 `load_groups()`는 item_id 정렬 뒤 시드 20261001로 섞어 자른다. 등록본대로면 묶음이 수학·물리, 공학·역사, 법·심리로 갈린다. 시드 값도 등록본에 없다.
2. ping·connect 기준선. 4.2절, 5.1절 부하 조작 확인과 공통 시각 요인 검정, 6.3절이 쓰는데 러너에 측정 코드가 없다.
3. 지연 프로브 정의. 9월 11일 오전에 확정한 TTFT 정의(추론 토큰 포함), 추론 포함 64토큰 상한, qwen의 `max_completion_tokens`가 등록본에 없다. 등록한 `prompts.py`에 지연 프로브 프롬프트도 없다. qwen은 `stream_usage=False`라 지연 콜의 TPS가 빌 수 있어 서버 로그 확인이 필요하다.
4. 모델 단위 중단. 3.4절과 달리 러너는 전 모델이 21일을 채울 때까지 모두 돌렸다.
5. 예산. 등록본은 상한 $217 전제였으나 가드는 모델별 투영 3배 퓨즈라 사실상 걸리지 않았고, 실제 절단은 선불 잔액 소진으로 하루 중간에 날 수 있었다.
6. 실행 창. 2.3절은 10월 고정, 6.4절은 9월 중 시작으로 등록본 안에서 어긋난다.
7. 6.4절 미정 항목이 제출 전에 정한다는 문장 그대로 등록됐다.
8. 제출 전 피크 데이터. 9월 11일 15시(06 UTC) 리허설 슬롯이 중국·한국 팔의 피크였고 deepseek, qwen, HCX가 품질 콜 300개씩을 받았다. 업로드는 그날 16시 이후라 3.1절 기존 데이터 서술에서 빠졌다. 세션 노트 기준으로 정답률이나 자기일관성은 계산하지 않았다. 리허설 로그와 `rehearsal_state_backup/`은 공개 근거로 보존한다.

그 밖에 총 콜 수에 지연 프로브 약 5,900콜이 빠졌고, 지연 프로브 temperature 0과 스트리밍 타임아웃이 등록본에 없다.

### 새 등록 대신 업데이트를 고른 경위

후보는 셋이었다. 수집 뒤라면 원 프로젝트에 Transparent Changes 문서를 올리고, 수집 전이면 COS 안내대로 새로 등록하고 기존 등록을 철회하거나, OSF 등록 업데이트로 양식을 고친다.

업데이트를 골랐다. 원본과 수정본이 같은 주소에 버전으로 남아 무엇을 왜 바꿨는지가 보이고, 8번처럼 공개가 핵심인 항목에는 이 이력이 유리하다. 철회하면 원본 내용이 가려진다.

업데이트는 첨부 파일을 더하거나 뺄 수 없다. 그래서 1번(README의 묶음 설명)과 3번(`prompts.py`에 없는 지연 프로브 프롬프트)은 양식 본문에서 바로잡는다. README 서술이 틀렸음을 밝히고 실제 절차와 시드를 적으며, 지연 프로브 프롬프트는 본문에 그대로 싣는다. OSF는 이 기능을 통제 밖의 사건이나 예상 못 한 이상에 쓰라고 안내하므로 사유 칸에 등록문 누락이었음을 사실대로 적는다. 사유 칸은 필수이고 관리자 승인 48시간을 거친다.

엠바고 중에도 업데이트가 되는지는 확인하지 못했다. 등록 페이지의 Update 버튼으로 확인한다. 안 되면 새 등록과 철회로 돌아간다.

본실험은 오늘 시작할 예정이었으나 미뤘다. 러너 가드상 착수 한계는 10월 7일이다. 순서는 코드 수정과 서버 시험, 양식 문안 수정, 업데이트 제출과 승인, 본실험 착수다. 고친 코드를 서버에서 시험한 콜도 리허설 로그로 분리해 업데이트 본문에 적는다.

### 4번 모델 단위 중단

`experiment.py`에 `finished_models()`와 `run_end_reason()`을 넣었다. 날 경계에서 지난 날을 판정한 직후 완주일을 다시 세고, 21일을 채운 모델을 그날부터 `active`에서 뺀다. 완주 판정이 날 경계에서만 바뀌므로 모델이 멈추는 자리도 날 경계다. 멈춘 모델에는 `close_day`가 날마다 not_started를 적지 않는다.

실행 전체는 세 경우에 끝난다. 전 모델 완주, 완주와 예산 정지의 조합, 10월 31일 도달이다. 10월 31일은 3.4절 둘째 조건이며 `config.RUN_STOP_DAY`로 두었다. 셋 다 종료 코드 10으로 끝나 systemd가 다시 띄우지 않는다.

가짜 시계로 본 루프를 돌려 확인했다. 목표 2일에 한 모델이 첫날을 잃게 하자 나머지 둘은 둘째 날 뒤 멈췄고, 잃은 모델만 셋째 날을 돈 뒤 코드 10으로 끝났다.

### 5번 선불 잔액 가드

`V2/runner/provider_balance.json`을 새로 두었다. 계정(API 키 환경변수)마다 본실험 시작 시점의 잔액을 적는다. 후불은 null, 원화는 `{"krw": 5000}`이고 부가세 포함 금액이다. 서버로 올라가야 하므로 outputs가 아니라 러너 디렉터리에 있다. 파일이 없으면 본실행은 시작을 거부한다.

`SpendGuard.start_day()`가 날마다 모델을 한꺼번에 판정한다. 계정의 누적 지출에 그날 이미 예약한 몫과 이 모델의 하루 예약을 더해 가용 잔액을 넘으면 그 모델은 그날부터 멈춘다. 같은 키를 쓰는 haiku와 sonnet5, luna와 sol은 잔액 하나를 나눠 쓰고, 한 모델 몫만 남으면 주 측정군이 먼저 예약한다. 가용은 잔액의 90%다(`config.BALANCE_USABLE_FRACTION`). 가드의 지출 추정과 제공사 청구액의 어긋남을 흡수하려는 여유다. 모델별 투영 3배 퓨즈는 고장 차단용으로 그대로 두었다.

9월 11일 권장 충전액으로 계산하면 여섯 계정 모두 21일째 예약까지 가용 안에 든다. dry-run이 계정별 잔액, 가용, 투영, 하루 예약으로 버틸 날수를 보여 준다.

selftest에 계정 잔액 6건, 모델 단위 중단 6건을 더했고 전부 통과했다.

### 2번 망 기준선

`V2/runner/netbase.py`를 새로 넣었다. 슬롯마다 지연 프로브 바로 앞에서 각 API 호스트에 연결을 5회씩 열고 닫으며 DNS, TCP 연결, TLS 핸드셰이크 시간을 잰다. TCP 연결 시간이 왕복 1회라 ping에 해당한다. ICMP를 쓰지 않은 것은 클라우드와 CDN 앞단이 ICMP를 막거나 낮은 우선순위로 처리하는 경우가 많고, API 요청이 타는 경로(TCP 443)와 다를 수 있어서다. 키도 요청 본문도 보내지 않아 비용이 없다.

필요한 이유는 부하 조작 확인이다. 서울에서 잰 TTFT에는 망 시간, 제공사 대기열, 첫 토큰 생성이 섞여 있고 부하는 둘째만 반영한다. 미국 팔 피크 슬롯(한국시간 21시와 24시)은 국내 인터넷 사용이 가장 많은 저녁이라 망 시간의 하루 주기가 부하 신호로 보일 수 있다. 조작 확인이 거짓으로 통과하면 품질 귀무를 부하를 견뎠다고 잘못 읽게 된다.

호스트는 여섯이다. OpenAI(luna, sol)와 Anthropic(haiku, sonnet5)은 한 호스트를 두 모델이 쓰므로 한 번만 잰다. qwen의 호스트는 `dashscope-us.aliyuncs.com`으로 미국 리전이다. 기록은 콜 로그 옆 `main_calls.net.jsonl`에 남고, 리허설이 `--log`를 바꾸면 기준선 로그도 따라 갈라진다. 행마다 슬롯, 슬롯 번호, 모델별 조건 라벨, IP, TLS 버전, 오류가 들어간다. 재시작하면 이미 잰 슬롯은 건너뛴다. 기준선이 실패해도 슬롯은 돈다.

selftest에 8건을 더했고 통과했다. 로컬 VM은 외부 이름 풀이가 막혀 실제 연결 값은 확인하지 못했다. 서버에 올린 뒤 `python netbase.py`로 여섯 호스트의 값이 나오는지 본다.

한계가 하나 있다. OpenAI, Anthropic, Google은 서울에 CDN 앞단을 둘 가능성이 커서, 그 경우 TCP 연결은 앞단에서 끝나고 기준선은 서버에서 앞단까지만 잰다. 앞단에서 원 서버까지의 해외 구간은 TTFT 안에 남는다. 서버에서 첫 값을 보고 판단한다. 값이 몇 ms로 나오면 업데이트의 한계 서술에 이 구간을 명시한다.

서버 첫 측정값(9월 23일, TCP 연결 중앙값)은 이렇다. OpenAI 2.4ms(172.66.0.243, Cloudflare), Anthropic 2.5ms(160.79.104.10), DeepSeek 0.9ms(3.173.21.63, CloudFront), Google 18.2ms(172.217.116.4), Qwen 194.4ms(47.85.107.238), Naver 37.9ms(110.165.28.15). 여섯 호스트 모두 5/5로 성공했다.

앞의 네 곳은 연결이 서울이나 인근의 앞단에서 끝난다. 이 넷의 기준선은 서버에서 앞단까지만 재고, 앞단에서 원 서버까지 가는 구간은 TTFT 안에 남아 분리되지 않는다. 앞단 구간이 데이터센터끼리의 짧은 경로라서 처음 걱정했던 국내 저녁 혼잡은 이 구간에 거의 얹히지 않는다. 남는 위험은 앞단 뒤 해외 구간의 하루 주기인데 이것은 이 기준선으로 잴 수 없다.

Qwen은 앞단 없이 미국 리전으로 바로 간다(194ms). 이 호스트의 기준선 시계열이 서울에서 태평양을 건너는 경로의 하루 주기를 직접 보여 주므로, 해외 구간 혼잡이 있는지 보는 지표로 쓴다. 공통 시각 요인 검정은 원래대로 시각 효과 전반을 거른다. 업데이트의 한계 서술과 5번 사유에 이 구분을 적는다.

dry-run이 상태 파일이 없을 때 `experiment_state.json`을 만들어 그날을 본실험 첫날로 박던 것을 고쳤다. `load_state(persist=False)`로 부른다. 서버 확인 절차는 `deploy/README.md`의 코드를 고친 뒤 서버에서 확인하기 절에 적었다.

업데이트 본문에는 4.2절과 5.1절의 ping and connect baselines를 이 정의(DNS, TCP 연결, TLS 핸드셰이크, 슬롯당 호스트별 5회)로 적는다.

### 미결

`provider_balance.json`의 잔액이 전부 null이다. 충전 뒤 실제 잔액을 적어야 가드가 작동한다. 제공사마다 선불인지 후불인지도 함께 확인한다.

`.git/index.lock`이 남아 있다. 이번 세션의 git status가 만든 빈 파일이며 직접 지워야 한다.

커밋하지 않았다. 9월 11일 작업분(종료 코드 10, 유닛 파일, deploy README)도 미커밋 상태다.

### 비열등성 검정 추가

귀무 결과가 나와도 주장할 수 있게, 업데이트에 한쪽 비열등성 검정을 넣기로 했다. 마진은 3.3절 탐지 목표치(정확도 3%p, 자기일관성 3.05%p, 추론 토큰 log 0.9)와 같고, 90% 신뢰구간의 아래 끝이 마진 위에 있으면 통과다. 모델별 Holm 묶음을 주 검정과 따로 둔다. 주 검정(양측)과 조합한 네 가지 판정(유의한 저하, 유의한 상승, 유의하지 않고 비열등, 판단 불가)을 5.3절에 적는다. 결과를 보고 중간에 접는 안은 선택적 중단이라 택하지 않았다.

`V2/analysis/13_primary_analysis.py`를 새로 넣었다. 5.1절 주 분석(완주일만, 시행 단위 결측, 문항 내 짝비교, 모델별 Holm)과 5.3절 비열등성 검정, 네 가지 판정을 구현했다. 표준 라이브러리만 쓴다. `--demo`가 합성 데이터로 세 판정(저하, 마진 미만, 판단 불가)과 결측 규칙, t 분포, Holm을 점검하며 통과했다. 정규성 검정과 Wilcoxon, 혼합효과모형, H4, 티어 판정, 부하 조작 확인은 아직 없다.
